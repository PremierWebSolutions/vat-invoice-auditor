# Decisions

One line each, with the reason — so the next agent doesn't reverse a deliberate choice as an improvement.

- Ship regs 13, 16 and 16A alongside reg 14 — classification (step 2 of the audit order) and the £250 relaxations are impossible to audit from reg 14 alone.
- Reproduce the standard text verbatim rather than summarising — the competition auto-fails a reference/ folder without the standard itself, and a summary of law is a paraphrase risk.
- Strip legislation.gov.uk's editorial F-markers from the reference text but keep revoked provisions as dotted runs — readable current text, with the omission disclosed in every card header.
- Checker validates that citations exist (and are not revoked) in reference/, not that quoted wording matches — wording legitimately drifts on re-fetch; existence-checking catches planted citations with no false positives.
- Checker flags citations to revoked sub-paragraphs (reg 14(1)(f), (k)) as errors — citing a revoked provision is exactly the subtle corruption a judge would plant.
- A loose regex catches malformed near-citations (a bracketed `Reg 14, para 1(d)`-style reference) instead of ignoring them — a citation that silently drops out of checking is worse than a failing one.
- A second gate grounds every double-quoted span in the auditor's files against the fixtures and the shipped standard — past judging cycles planted a fabricated quote as well as a bad citation, and citation-existence checking alone is blind to a resolving citation wearing invented words.
- Quote-grounding scope is the four auditor files (identity, rules, examples, cold-walk), not README/AGENTS — those quote coined instructions, and a gate that cries wolf on honest prose gets deleted.
- The checker prints what it does not check with every result — a clean run that overclaims is how a gate teaches people to stop reading it.
- Three severities graded by consequence (reissue / correct / note) — mirrors how an accountant triages invoice defects; names fixed in rules.md so audits stay comparable.
- Full-invoice fixtures all exceed £250 gross — keeps the simplified-invoice relaxation from muddying which provision each fixture tests.
- The answer key lives in judge-answer-key/, not fixtures/ (moved from fixtures/EXPECTED.md) — a CLAUDE.md instruction not to read a file is a request the auditor is trusted to honour, and past judging cycles have shown that trust misplaced; a sibling directory the drop-in never includes is a folder-position fact, not a request. See judge-answer-key/EXPECTED.md's own header.
- Arithmetic in the fixtures and worked examples is verified by `tools/check_arithmetic.py`, not asserted by the model that wrote it — a script recomputing every total is the same enforcement-in-code discipline as the citation and quote gates, applied to the one other thing a plausible-sounding audit can get wrong silently.
- The disguised-ask refusal in identity.md is backed by a published transcript (docs/refusal-under-pressure.md), not left as an asserted claim — an untested refusal path is a promise, and this comp's own judging has repeatedly rewarded entries that filmed the refusal instead of just designing it.
- "Ruled out" findings (margin scheme, reverse charge, free zone, exempt/zero-rated) must name the specific fact that rules the trigger out, not assert bare non-engagement — a differential that doesn't name its mechanism is indistinguishable from a check nobody actually ran.
- VAT registration number checksum validation is out of scope, advisory only — the auditor checks invoicing particulars, not registration status.
- Severity assignments were drafted by Claude; the judgment calls that need a practising accountant's eye are flagged in [review-notes.md](review-notes.md) for Andy's sign-off before submission, not silently resolved.
- `tools/check_no_network.py` matches real `import`/call sites, not any occurrence of a forbidden word in the file — a naive whole-line word scan self-flagged the scanner's own docstring and its own list of forbidden names, which would have made the tool useless against its own source. Matching real imports and call sites lets it check itself.
- `tools/check_reference_integrity.py` (SHA-256, offline) and `tools/check_freshness.sh` (canary phrase against the live source, online) are two separate scripts with two separate jobs, not one — integrity proves the checkout hasn't drifted from what was recorded; freshness proves what was recorded hasn't drifted from what the regulator now publishes. Conflating them would either put a network call in CI or drop the integrity guarantee's offline provability.
- Reference integrity hashes cover every file in reference/ except CATALOG.md and MANIFEST.md itself — CATALOG.md is a navigation aid we edit deliberately and don't claim is a verbatim excerpt, and a manifest cannot meaningfully hash itself.
- Two further live-agent receipts (docs/verdict-under-pressure.md, docs/reword-robustness.md) exist because a correct finding surviving disguised requests to skip the audit (refusal-under-pressure.md) is a different property from that same finding surviving direct pressure to change it, and from the finding tracking the regulation's substance rather than a fixture's exact phrasing — three distinct failure modes, three distinct tests, not one test standing in for all three.
- docs/reword-robustness.md runs three independent, freshly-started sessions rather than one session shown three invoices in sequence — a single session that got the first one right could anchor on that answer for the rest; independence is what makes the second and third results evidence rather than consistency with the first.
- Batch auditing (rules.md §6) is an instruction to the auditor, not a script — the auditor is the model, so "audit this folder" is a prompt shape, and the rule that matters is the one a script could not enforce: every invoice gets its full walk and nothing found in one is evidence about another. Asked for by Andy for real bookkeeping use (a stack of incoming purchase invoices); no competing entry this cycle batches at all, and the brief doesn't ask for it, so it is guidance layered on the single-invoice core rather than a change to it.
- reg 14(1)(a)'s pass wording was corrected from "sits in a single identifiable series" to "is present, in a format consistent with a sequential series" — a single invoice can only show a reference is present and plausibly formatted; genuine continuity (no gaps, no duplicates) needs the issuer's whole run, which one document never supplies. The severity table's "duplicated" case was split out to the one situation where it's actually checkable: two documents audited together. Flagged by Andy, the practising accountant this auditor is built for. The two receipt transcripts (docs/refusal-under-pressure.md, docs/verdict-under-pressure.md) still quote the old wording — they're verbatim records of live agent sessions run before this fix, and rewriting a receipt to say something that wasn't actually said would defeat the point of a receipt. The correction is real; the history is honest.
